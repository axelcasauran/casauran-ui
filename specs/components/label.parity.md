## Provenance and clean-room review

The mandatory local-only preflight passed against snapshot
`2b68481b897ab216625fd264a10fb323fc0071c2a589f893c488d13e91ff4862`. Every examined path — four
component pages, five API pages, eight package and cross-cutting pages, and twelve sibling-component
pages read only to fix this stage's boundary — is recorded in `label.reference-analysis.md`,

used as implementation input. The implementation was produced from `label.spec.md`; no source, CSS,
theme value, class name, asset, bundle, private architecture, undocumented DOM, online fallback, or
runnable example file was used as implementation input.

This is the first stage whose reference domain holds four sibling components. Three of them are
separate registry entries owned by later stages, and the one-stage rule forbids shipping them here;
rows 36 to 39 record that boundary explicitly rather than leaving it implied.

## Disposition vocabulary

Every materially relevant capability carries exactly one disposition: `IMPLEMENTED`,
`IMPLEMENTED_DIFFERENTLY`, `NOT_APPLICABLE`, `INTENTIONALLY_DIVERGED`,
`DEFERRED_TO_DECLARED_DEPENDENCY`, or `BLOCKED`. A silent omission and an unowned deferral are not
acceptable final states. Deferral names the owning stage.

## Manual accessibility and visual review

The rendered semantics and the Chromium visual baseline were inspected by hand. The review confirmed
that a text field, a checkbox and a radio each take their accessible name from the associated
caption; that clicking a caption focuses the field and toggles the checkbox with no component
JavaScript; that a widget with no native control is named through `aria-labelledby` while its
caption carries no `for`; that a required field is announced as its name followed by the marker
word, separated rather than run together; that a disabled caption is dimmed and a disabled-and-invalid
caption reads as disabled while still reflecting both states; that an omitted caption is invisible
yet holds its row's alignment; that a long caption wraps across four lines at a narrow width with its
marker still in the text flow; that a caption containing markup is drawn as characters; and that in
the right-to-left panel the marker sits to the left of the caption, which is the reading-order
position. The review makes no claim of an external screen-reader certification matrix that was not
executed.

One accessibility defect was found by this review process and fixed before completion: the marker
originally contributed to the accessible name with no separator, so a required field was computed as
its name joined directly to the marker word. Accessible-name computation concatenates the text of
inline descendants without inserting a space, and a CSS margin contributes nothing to a name. The
component now renders a literal space, the browser case asserts the computed name, and the unit case
asserts the separator survives in the markup.

## Deliberate independent improvements

- The marker vocabulary covers required as well as optional, which is the more common convention and
  the one with an accessibility contract behind it.
- The marker word is a mandatory supplied string rather than an ambient lookup, so an untranslated
  marker is a build failure instead of a defect a translator finds later — and the component needs
  no localization provider, no message catalogue, and no client boundary.
- The marker is separated from the caption in the accessible name, not only on screen.
- Validity is expressed positively, so no caller has to read a double negative.
- Precedence between the disabled and invalid presentations is decided, documented and tested rather
  than left to whichever rule happens to be written last.
- Both editor states stay reflected on the element even when one wins visually, so a test or a
  consumer selector sees the full state rather than the resolved one.
- Direction needs no property at all, because the stylesheet is logical throughout.
- The caption is `ReactNode`, so a value that would fail at render fails at build instead.

## Gaps, debt, and boundary

No in-scope parity gap, architecture debt, dependency debt, security exception, or unexplained
