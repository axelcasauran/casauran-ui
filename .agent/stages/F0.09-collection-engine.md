## Outcome

Outcome: COMPLETE

F0.09 establishes the framework-neutral internal collection engine for immutable ordered/tree
snapshots, mutation-safe keyed registration, enabled active-item movement, deterministic
selection, visible-tree projection, and caller-timed typeahead. Ownership, invariant diagnostics,
strict typing, SSR safety, large-data stack safety, security behavior, documentation, mechanical
validation, and cross-browser production-host evidence are complete without introducing a public
component or advancing F0.10.

## Delivered scope

- Added a canonical versioned collection-engine registry and JSON Schema with six exact
  capabilities, per-capability evidence, owner package, and explicit owned/excluded boundaries.
- Implemented immutable snapshots with string/number keys, deterministic depth-first preorder,
  map-backed parent/child/depth lookup, enabled-key projection, and stable diagnostic codes for
  duplicate keys, missing parents, self-parenting, and parent cycles.
- Implemented mutation-safe keyed registration with stable insertion order, replacement without
  reordering, explicit unregister/clear, and token-aware cleanup that cannot remove a newer
  registration.
- Implemented logical previous/next/first/last active movement, disabled-item skipping, optional
  looping, deterministic none/single/multiple selection, toggle/range/add-range/clear intents, and
  separate active/selected identities.
- Implemented iterative visible-tree projection and caller-timed typeahead with timeout reset,
  repeated-character cycling, wraparound, disabled-item skipping, deterministic default Unicode
  normalization, and an injectable pure normalization seam.
- Added five validator regression tests, thirteen engine unit tests including a 10,000-item deep
  tree and markup-like untrusted text, and three production Server Component scenarios per browser
  for SSR, ordering, active/selection, and typeahead results.
- Added the internal collections package to the visual-test workspace only; no external runtime
  dependency, React binding, public export, client boundary, browser global, or timer was added.
- Updated capability lifecycle, ownership/CODEOWNERS, architecture/security/performance/Next.js
  and testing policies, matrices, package/docs/test navigation, contributor guidance, the root
  command surface, mechanical governance, and the prior F0.08 lifecycle validator.

## Enterprise applicability

- Functionality: applicable; later list/tree/composite components receive one canonical identity,
  registration, navigation, selection, visibility, and typeahead engine without duplicated local
  algorithms.
- Typing/API: applicable; string/number keys and generic metadata infer under strict TypeScript,
  all output is readonly, diagnostics use stable codes, and no third-party type leaks. The package
  remains internal and is not a supported public consumer API.
- Accessibility: indirectly applicable; active, selected, disabled, expanded, and focused
  identities remain separate. The engine renders no semantics and certifies no APG pattern;
  component stages retain role/name/state, focus, keyboard, announcement, target-size, and manual
  review obligations.
- Keyboard/pointer/touch/RTL/IME: logical movement is direction-neutral; components map actual
  events, orientation, RTL, paging, and pointer/touch behavior. Callers suppress composing input
  and submit committed typeahead text, preserving IME ownership outside the engine.
- Theming/density/responsive: not applicable to nonvisual algorithms; no token, CSS, layout,
  viewport, or media assumption exists.
- i18n: default matching is deterministic and ambient-locale-free; a caller may inject a pure
  normalization function from the i18n owner without transferring locale ownership.
- SSR/RSC: applicable and complete; modules have no React/client directive, random source, timer,
  effect, storage, or browser global, and the compiled root executes in a production Server
  Component route across three engines.
- Security: text/metadata are copied/compared only and never rendered, executed, serialized,
  fetched, or interpreted as HTML/URL. Markup-like text has negative unit evidence.
- Performance: snapshot construction and iterative tree traversal are linear, lookup is
  map-backed, and a deterministic 10,000-item deep-tree case proves stack safety. No universal
  timing or virtualization claim is made.
