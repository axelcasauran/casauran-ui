## Delivered scope

Exactly one public component, `Label`: the platform's form-caption primitive. It renders a native
`<label>` and supports the native association, the inverse association for an editor with no
labelable element, a three-value requirement vocabulary whose marker text is mandatory and supplied,
positive `invalid` and `disabled` reflections with a decided precedence between them, a deliberately
empty caption that holds a row's alignment, five reflected state attributes, a nine-token theming
seam, RTL, forced colours, SSR/RSC, and native attribute passthrough with three reserved props.

`registry/tokens/foundation.json` was extended at the token owner layer with the nine `Label`
component tokens. No primitive or semantic token was added, no shared engine was touched, and
`Button`, `Icon`, `SVGIcon` and `Typography` are unchanged.

The three sibling components in the same reference domain — the floating caption, the hint and the
error message — were deliberately not built. Each is a separate registry entry owned by `2.03`,
`2.01` and `2.02`, and shipping any of them here would have violated the one-stage rule.

## Decisions, debt, and blockers

- The native `label` relationship is the API. `htmlFor` is the React name for the element's own
  attribute, so what a caller writes is what the DOM contains.
- Click forwarding through a reference to the editor is rejected by the type. It duck-types another
  component's internals, cannot be typed, fails silently, and would put a client boundary and a
  listener on every caption in an application. This is the stage's defining divergence, recorded in
  advance in the reference analysis and as capability 6 of the parity audit.
- The marker word is supplied and mandatory whenever a marker is requested, so the component needs
  no localization provider, no message catalogue and no ambient locale read.
- The marker contributes a literal space to the accessible name. This was a real defect found by the
  browser accessible-name assertion during this stage and fixed before completion; the CSS gap is
  visual separation only and contributes nothing to a name.
- Validity is positive. Disabled presentation takes precedence over invalid, and both states stay
  reflected.
- No size or tone scale was added. A caption should match the control it names and the control that
  would set that scale has not shipped; the component tokens are the seam in the meantime.
- One deferral is recorded, owned by `1.06 Input` and `7.01 Form`, and it is an integration
  revalidation rather than a missing capability: Label is complete against every editor that exists
  today.
- The governed topic model titles the `content` topic "Icons, images, and content", which reads
  generically on a component with no artwork. The topic itself applies — the requirement marker and
  composed captions are content rules — and the title is owned by `F0.19`, is shared with four other
  routes, and is baked into their committed baselines. Renaming it is a documentation-foundation
  change rather than a component-stage one, so it was left alone deliberately rather than missed.
- Open, not owned by this stage: the Phase 0 re-certification recorded in `.agent/status.md`,
  including the Firefox and WebKit baseline set, the `theme-runtime` Chromium baseline, and the
  pinned Node 24.18.0 runtime.

## Boundary audit

at the declared owner of the token contract, not a second React component.

Deliberately not built: the floating caption variant (`2.03`), the hint message (`2.01`), the error

lookup; a size or tone scale; a direction property; support for nesting a control inside the
caption; caption-relative layout; a custom ref handle; a runtime class-replacement provider; and any
licensing, design-kit, theme-builder or utility-bridge surface. `1.06 Input` was not begun, and the
editor-side props — `required`, `aria-required`, `aria-invalid` and `disabled` — were deliberately
left to the control that owns them.
