# Stage F0.19: Documentation Interaction Foundation

Type: foundation
Status: not-started
Prompt: `.agent/prompts/foundation-stage.md`
Decision: `.agent/decisions/ADR-024-documentation-interaction-foundation.md`

## Objective

Give every component route a per-capability information architecture and a genuinely interactive
example harness, generated from a declared topic model so the shape holds across all 127 components
instead of being rebuilt per stage.

## Rationale and ownership decision

The `1.01 Button` revalidation on 2026-08-15 showed that documentation completeness and
documentation _experience_ are different problems. ADR-023 closed the completeness half: every
declared feature must be demonstrated, and enumerated features must preview every value. It cannot
close the other half, because the single-page route shape and the static example primitive are F0.18
contract clauses, and changing them affects every component route rather than any one component.

ADR-024 accepts F0.19 at the current ledger boundary after F0.18, following the ADR-020 precedent,
so the completed stage prefix stays truthful and `1.03` inherits the finished model rather than
being migrated afterwards.

## Scope

- A declared topic model naming the capability topics a component route may publish — overview,
  appearance, sizes, states, icons and content, events, forms, controlled state, keyboard,
  accessibility, globalization, performance, security, API, limitations — with required and optional
  topics distinguished.
- Route and nested-navigation generation from that model, replacing hand-authored single pages, with
  sidebar nesting and per-topic tables of contents.
- Migration of the existing Button and Icon routes with no content loss and continuity for published
  `/components/<slug>#section` deep links.
- An interactive example primitive: a narrow client island per example so toggles toggle and forms
  submit, with global theme, density and direction control left to the shell.
- One source of truth for example code, so displayed source is the code that renders or is
  mechanically verified against it.
- Extension of the ADR-023 coverage rule to resolve a feature's declared anchor against the topic
  that owns it.
- Browser and visual evidence for the new navigation, including keyboard and mobile behaviour, and a
  recorded hydration and bundle cost for the example islands.

## Dependencies

- Accepted ADRs 001, 003, 008, 009, 010, 013, 019, 020, 022, 023, 024, 999.
- Completed F0.18 documentation experience foundation.
- Existing supported `@casauran/react`, `@casauran/theme`, `@casauran/tokens`, and `@casauran/icons`
  exports only.

## Acceptance criteria

- Component documentation is reachable per capability topic, and the sidebar reflects the nesting.
- Routes and navigation are generated from the declared topic model; adding a component does not
  mean hand-writing topic pages.
- Every previously published component route and section anchor still resolves.
- Examples that demonstrate interactive behaviour are interactive, and their displayed source
  matches what renders.
- ADR-023 coverage still passes for every documented component under the new anchor resolution.
- Documentation client boundaries remain local example islands; route modules and the package root
  stay server-safe, and the validator describes the new allowed set rather than dropping the audit.
- Hydration and bundle cost of the example islands is measured and recorded.

## Boundary

Out of scope: per-example theme, density or direction switchers; a props playground; documentation
search; versioned documentation; any public component, token or API change; and any stage `1.03`
work. This stage ships no public component.
