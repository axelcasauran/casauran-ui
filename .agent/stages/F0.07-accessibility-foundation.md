## Outcome

Outcome: COMPLETE

F0.07 establishes the framework-neutral accessibility primitives required by later component,
collection, and overlay owners. Native focus inspection, one-shot focus, stateless roving focus,
direction-aware keyboard intent, text-only live regions, visually hidden content, ownership,
validation, documentation, and cross-browser evidence are complete without introducing a public
component or React abstraction.

## Delivered scope

- Added a canonical versioned accessibility-foundation registry and JSON Schema covering five
  owned capabilities, their exact exports, evidence classes, and future-stage exclusions.
- Implemented native focus/tabbability inspection and guarded programmatic focus without a focus
  trap, restoration lifecycle, browser-global module evaluation, or external dependency.
- Implemented stateless roving-tab-stop resolution and movement with disabled-item skipping,
  optional looping, first/last movement, and no collection registration or selection state.
- Implemented orientation- and direction-aware keyboard intent with RTL horizontal reversal,
  modifier filtering, activation/dismiss keys, and IME-composition protection.
- Implemented configurable live-region attributes and a coalescing controller that writes only
  `textContent`, plus a cascade-layered visually-hidden utility using logical sizing.
- Added five Node contract regression tests, ten strict Vitest tests, and six production browser
  cases per engine for SSR semantics, accessibility-tree output, keyboard/RTL/IME behavior, focus,
  live-region safety, and hidden-content rendering.
- Added a production Next.js fixture and a source-only private test bridge; the compiled package
  root remains the normal internal consumption path and no supported public export was added.
- Updated accessibility/security/Next.js architecture, capability state, ownership/CODEOWNERS,
  matrices, package guidance, contributor workflow, handbook, registry navigation, test guidance,
  README, and pull-request checks.

## Enterprise applicability

- Functionality: applicable; consumers can inspect tabbable descendants, focus durable targets,
  resolve/move a single tab stop, map keyboard input, announce text, and visually hide accessible
  content through explicit framework-neutral contracts.
- Typing/API: applicable; closed literal unions and structural DOM-like inputs infer without
  third-party type leakage. The package remains private/internal; no supported public Casauran API
  or stability promise was introduced.
- Accessibility: applicable; semantic HTML remains primary, APG semantics stay component-owned,
  native disabled/hidden/inert suppression is respected, one roving tab stop is enforced, focus is
  visible through the F0.06 theme, and live content remains in the accessibility tree.
- Keyboard, pointer, touch, and IME: keyboard behavior covers orientation, RTL, modifiers,
  activation, dismissal, Home/End, disabled skipping, looping, and composition safety. No pointer
  or touch gesture contract is introduced by these keyboard/focus primitives.
- Theming, density, forced colors, and reduced motion: the hidden utility consumes no copied theme
  values; visible focus inherits the established theme contract. No motion primitive is added.
- RTL/i18n: horizontal intent reverses under explicit RTL while DOM order and announcements remain
  text/locale-neutral. Message translation remains with the owning i18n/component layer.
- SSR/hydration/RSC: modules do not touch browser globals at evaluation, the stylesheet is static,
  the route prerenders, and all engines receive semantic server markup before client interaction.
- Security: live announcements accept text only and write `textContent`; markup-like untrusted
  input is verified as literal text. No HTML, URL, SVG, file, storage, network, or serialization
  escape hatch was introduced.
- Performance: focus queries are scoped, roving movement is linear in its provided item list, and
  live announcements coalesce scheduled writes. No universal timing or bundle-size claim is made.
- Responsive/adaptive: primitives do not own layout; logical CSS and inherited theme behavior avoid
  direction- or viewport-specific duplication.
- Integration/documentation: registry, schema, package seams, ownership, architecture, security,
  Next.js fixture, tests, commands, and contributor guidance are mutually aligned.
