### What changed

- **Capability gap closed.** `size="xs"` was added to the supported public API with tokenized
  spacing and typography, specification text, unit and browser coverage, docs, and a visual panel.
- **Geometry defect fixed.** Icon-only layout pinned its inline size to the default control size, so
  an icon-only `sm`, `lg` or `xs` action was not square. Both axes now resolve from one internal
  `--_csn-button-size` property, locked by a browser assertion that every size is square and the
  scale is monotonic.
- **Contrast defect fixed.** Found during manual visual review of the regenerated baseline:
  `outline`, `ghost` and `link` painted their text with the tone's _surface_ colour, so the neutral
  tone rendered pale grey text on the canvas. They now use the tone's text colour. A browser case
  asserts every transparent appearance matches the readable tone text colour and is not the control
  surface, and the visual matrix gained a neutral appearance row.
- **Deferred integration resolved.** The Button × Icon obligation left open when `1.02` closed is
  now evidenced: unit composition cases, a browser case proving composed artwork adds no second
  interactive element and no extra accessible name, a docs example, and a visual panel.
- **Documentation completed.** The docs route grew from six sections to sixteen, adding appearance
  and tone, sizes and shapes, states, icons/images/content, events, forms, controlled state,
  performance, security, and known limitations, plus a styling-hook table. The API table gained
  `radius`, `startContent`, `endContent`, `type`, `disabled` and `ref`, and its `appearance` default
  was corrected from `solid` to the implemented `soft`.
- **Two repository defects repaired**, both blocking this stage's gate. `pnpm lint` failed with
  7,368 parse errors on the vendored `kdocs` corpus, and `pnpm format:write` rewrote 9,164 vendored
  files, which modifies read-only competitor material and invalidates the pinned reference digest.
  The corpus is now excluded from both tools with the rationale recorded in each ignore file.
  `benchmarks/button.mjs` printed a hardcoded `win32 x64` environment regardless of the real
  platform, which made recorded performance evidence unverifiable; it now reports
  `process.platform` and `process.arch`. `scripts/generate-required-by.mjs` emitted JSON that
  Prettier rejects, so regenerating a tracked artifact broke the format gate — the exact
  non-idempotent pattern §29 forbids; it now emits the Prettier shape and reproduces the committed
  file byte for byte.
- **Guard added.** `pnpm validate:capability-completeness` is the 38th governed validator, with
  `.agent/capability-completeness.json` and fifteen rejection tests.
- **Documentation coverage guard added** after review of the running documentation showed the
  remaining half of B-7: the route still previewed no `outline`, `ghost` or `link` button, because
  nothing bound the declared feature list to what the page renders. `ADR-023` adds
  `featureCoverage` to the component registry — every feature is satisfied by a `preview`, a
  `section`, or a named `fixture`, and an enumerated feature previews **every** value as an explicit
  prop assignment. `pnpm validate:documentation-experience` enforces it with thirteen rejection
  tests, and a browser case reads the registry and asserts each declared value really renders. The
  rule immediately found three `radius` values that had never been previewed; they are now
  documented.
- **`F0.19` specified, not built.** Per-capability documentation routes and an interactive example
  harness are documentation-foundation work affecting all 127 routes, so `ADR-024` inserts
  `F0.19 Documentation Interaction Foundation` at the ledger boundary after `F0.18` with a full
  specification, and this stage builds none of it. The `F0.18` boundary assertion was generalised
  from "immediately between 1.02 and 1.03" to "after 1.02, with no public component stage before
  1.03", so a governed stage can be inserted there at all; its intent is preserved and locked.
