### What changed

- **Contrast defect fixed.** `tone="inherit"`, the default, painted the theme's primary text colour
  rather than `currentColor`, so composed artwork ignored its context: an Icon inside a solid accent
  Button rendered dark artwork on a saturated fill. A browser case now pins a default-tone icon's
  computed colour to its container's and to a composed Button's label colour, and the visual matrix
  gained a composition panel and a toned-text sample.
- **Two accessibility defects fixed.** A blank or whitespace-only `label` published `role="img"`
  with an empty accessible name; it now keeps the icon decorative, and a real label is trimmed.
  `tabIndex` was forwarded, so an `aria-hidden` element could take a tab stop; it is now rejected by
  the type along with `role`, `aria-hidden` and `aria-label`, which were accepted and then silently
  overwritten.
- **Type-safety gap closed.** `name` was `string`, so the route's only example shipped
  `name="check"` against a catalog that had no `check` definition and rendered a labelled empty
  element. `name` is now the `IconName` catalog union, `isIconName` narrows a name that crossed a
  runtime boundary, and an unnarrowed unknown name still fails closed. Four definitions the tone
  scale and documentation genuinely need — `check`, `error`, `info`, `warning` — were added, taking
  the catalog to fourteen.
- **Ambiguous API value removed.** The `info` tone resolved to the same custom property as `accent`,
  so two public values were indistinguishable. It is removed, and Icon and Button now share one tone
  vocabulary. Recorded for this stage by the Button revalidation.
- **Token seam made uniform.** `md` and `inherit` had no rule of their own and fell through to the
  theme root, so a consumer override applied to a default but lost to any explicit value. Every
  enumerated size and tone now assigns its component token at the same specificity, and the
  documented seam is the `overrides` cascade layer.
- **Documentation completed.** The route grew from five topics to ten and from one example to seven,
  adding appearance and tone, sizes and shapes, icons/images and content, Next.js and rendering,
  performance, and known limitations. The API table's `tone` union, its default, and the `flip`
  default were wrong and are corrected, and a styling-hook table was added.
- **Documentation coverage debt cleared.** `registry/components/icon.json` declares
  `featureCoverage` for all eighteen features, previewing every one of the seven sizes, seven tones
  and four flip values as an explicit prop assignment. `pendingCoverage` is now empty.
- **Deferred obligation resolved.** `benchmarks/icon.mjs` printed no environment, which the Button
  revalidation left to this stage. It now reports the Node version, platform, architecture and
  ceiling, and `.agent/performance-budgets.md` records both the original and the revalidation
  results with their environments.
- **Another stage's baseline regenerated, deliberately.** The inherited-colour fix changed twenty
  pixels of `button-matrix-chromium-linux.png` — the `+` glyph in Button's composition panel is now
  readable on its solid fill — and the documentation work changed both `docs-shell` baselines, whose
  navigation now lists Icon's ten topics. All three were regenerated and reviewed image by image.
  No prior-stage ledger text was edited. `theme-runtime`'s missing Linux baseline belongs to a Phase
  0 foundation stage and was left alone.
