# Stage F0.18: Documentation Experience Foundation

Type: foundation
Status: complete
Completion date: 2026-08-14
Prompt: `.agent/prompts/foundation-stage.md`
Decision: `.agent/decisions/ADR-020-documentation-experience-foundation.md`

## Objective

Establish the reusable, production-quality `apps/docs` experience required by every subsequent
public component stage without adding a public component or turning `apps/playground` into the
customer documentation portal.

## Rationale and ownership decision

The approved roadmap previously assigned the Next.js host topology but no stage owned the reusable
documentation platform. ADR-020 accepts F0.18 at the current ledger boundary after 1.02 so the
already-completed stage prefix remains truthful.

## Scope

- Casauran-branded global shell, header, category/component navigation, page table of contents,
  responsive layout, stable routes, and deep-linkable sections.
- Reusable docs-only page, example/source, API reference, accessibility/keyboard, and callout
  presentation structures.
- Light/dark, comfortable/compact, and LTR/RTL presentation controls behind a local client
  boundary.
- Search-ready, registry-derived navigation metadata and a deterministic metadata endpoint.
- WCAG 2.2 AA application behavior, SSR/RSC-safe architecture, production build evidence, and
  deterministic multi-browser docs-shell visual coverage.

## Dependencies

- Accepted ADRs 001, 003, 008, 009, 010, 013, 019, 999, and ADR-020.
- Completed F0.04-F0.08 host/theme/accessibility/state foundations.
- Existing supported `@casauran/react`, `@casauran/theme`, `@casauran/tokens`, and
  `@casauran/icons` exports only.

## Acceptance criteria

- `apps/docs` is visibly and structurally the canonical customer documentation experience;
  `apps/playground` remains a separate engineering sandbox.
- Existing `/components/button` and `/components/icon` routes and all page section anchors remain
  stable under the shared shell.
- Documentation primitives cover examples/source, API, accessibility, keyboard, and callouts.
- Registry-derived metadata is deterministic, search-ready, escaped as data, and browser-tested.
- Theme, density, direction, responsive navigation, keyboard access, focus visibility, forced
  colors, reduced motion, SSR, hydration, and RSC boundaries are verified as applicable.
- Focused contract tests, strict types, production docs build, `pnpm validate`, and manual in-app
  browser visual review pass.

## Boundary

Do not implement SVGIcon, Button changes, a new public component, a public documentation package,
external search/CMS/analytics, Storybook, deployment, or playground replacement.

## Exit evidence

All acceptance criteria passed and the stage is closed through the governed completion record below.

## Outcome

Outcome: COMPLETE

ADR-020 accepted F0.18 because no approved stage owned the reusable customer documentation
experience. The stage establishes `apps/docs` as a production-quality, independently designed
Casauran portal with shared information architecture, docs-only presentation primitives,
registry-derived metadata, minimal client boundaries, and deterministic production browser
evidence. Existing Button and Icon documentation now use the foundation. `apps/playground` remains
an engineering sandbox, and stage 1.03 remains not-started.

## Delivered scope

- Added the branded global shell with skip navigation, sticky header, desktop category/component
  sidebar, native mobile disclosure navigation, page content landmark, and page-level table of
  contents.
- Added private reusable `DocsPage`, `DocsSection`, `Example`, source panel, `ApiReference`,
  `KeyboardTable`, `AccessibilityChecklist`, and tone-aware `Callout` structures.
- Added stable `/components/button`, `/components/icon`, section-anchor, and `/docs-index.json`
  contracts. The normalized search-ready index derives stage IDs/status from the canonical stage
  registry and contains no timestamp, external provider, or client registry payload.
- Added a Casauran-specific warm editorial visual system with light/dark, comfortable/compact,
  LTR/RTL, responsive, forced-color, and reduced-motion presentation.
- Confined hydration to current-route annotation and enumerated presentation controls. All content,
  metadata, page structure, examples, API/accessibility tables, and shell composition remain server
  rendered by default.
- Migrated Button and Icon pages to executable public-API examples and complete reusable overview,
  API, accessibility/keyboard, theme/RTL, SSR, i18n, and security structures.
- Added deterministic docs-host SSR, deep-link, metadata, runtime-error, keyboard, preference,
  mobile-reflow, and six visual baseline checks across Chromium, Firefox, and WebKit.
- Kept the four-host topology: docs is customer-facing, playground is the engineering sandbox,
  visual-tests is the fixture host, and Playwright now starts both relevant production hosts.

## Enterprise applicability

- Functionality/integration: complete for the reusable docs application contract. Stable routes,
  anchors, navigation, content primitives, metadata, registry integration, and host separation are
  implemented and tested.
- Typing/API: all private contracts are strict TypeScript. No public package/API or third-party
  type was added; later stages consume private app structures and supported public component APIs.
- Accessibility/input: semantic landmarks, heading order, skip navigation, labelled navigation and
  controls, current-page state, notes, captions/headers, scrollable code/tables, visible focus,
  keyboard activation, touch disclosure, 320-pixel reflow, forced colors, and reduced motion are
  covered. Chromium/Firefox prove first-Tab skip-link order; WebKit's Windows harness verifies
  direct keyboard activation because host full-keyboard-access policy does not expose link tabbing.
- Security: repository-authored content is React-escaped. No raw HTML, Markdown bypass, remote
  fetch, executable source, dynamic module path, storage bootstrap, URL sink, analytics, CMS, or
  external search boundary exists. The static JSON index is bounded and CSP-compatible.
- Performance: the mostly server-rendered shell has two small client modules; registry derivation is
  linear in the bounded stage ledger and is not shipped to the client. No universal speed or bundle
  claim is made and no performance blocker was observed in production builds/browser runs.
- Theme/density/RTL/i18n: explicit light/dark, comfortable/compact, LTR/RTL, forced-color, and
  reduced-motion presentation is complete. Content is English only at this stage; the shell owns no
  product message catalog and future localized docs remain an application concern.
- SSR/hydration/RSC/responsive: routes and metadata are server-first and deterministic; only current
  links and preference buttons hydrate. Direct SSR, deep links, runtime logs, desktop/mobile
  screenshots, and all production builds pass.
- Documentation: the docs application README and governing policies describe ownership, future
  stage composition, trust boundaries, commands, and host separation.

## Decisions, debt, and blockers

- ADR-020 is accepted from the maintainer-directed request with evidence, options, impact,
  migration/rollback, and revisit triggers. No dependency ADR is needed because runtime
  dependencies are unchanged.
- Full search, CMS, analytics, user preference persistence, interactive code execution, and
  deployment are deliberately excluded, not hidden debt. Each would add a real integration or
  security boundary and requires its governing workflow when requested.
- The WebKit Tab-order assertion is limited by the Windows browser harness's full-keyboard-access
  policy; direct skip-link keyboard activation still passes there, while Chromium and Firefox prove
  first-Tab order. This is recorded evidence scope, not an application defect or blocker.
- No in-scope blocker remains.

## Boundary audit

- No Button/Icon implementation or supported API was changed by F0.18; their existing public APIs
  are only consumed in documentation examples.
- No SVGIcon source, registry lifecycle, specification, parity claim, route, or public export was
  created or advanced. Stage 1.03 remains `not-started`/`unreviewed`.
- No public package, runtime dependency, Storybook, search vendor, CMS, analytics, authentication,
  deployment, or proprietary reference asset/value/DOM/CSS/architecture was added.
- No Kendo/Telerik document body, online source, repository, live site, search engine, tutorial, or
  model-memory fallback was used. This foundation follows Casauran's independent specification;
  reference provenance and component mappings are unchanged.
- `apps/playground` was not converted into customer documentation and retains its existing sandbox
  content. Stage index and program status agree: F0.18 is complete, active stage is none, and 1.03
