## Enterprise applicability

- Functionality: applicable; the operating lifecycle, routing coverage, ownership, completion,
  blocking, and boundary behavior are documented and mechanically validated.
- Typing and public API: no consumer TypeScript/runtime API is introduced; the internal JSON
  contract has a versioned schema and structural runtime validation.
- Accessibility, keyboard, touch, and IME: no interactive UI is introduced; the routing contract
  makes accessibility mandatory for public components and provides accessibility and
  internationalization-sensitive routes.
- Security: applicable; external/reference/tool output is treated as untrusted data, secrets are
  excluded from prompts/evidence, and security-sensitive work adds the security workflow and
  skill.
- Performance: no runtime performance claim or product path is introduced; large-data and
  performance routes are explicit.
- Theming, density, RTL, and i18n: no rendered surface is introduced; theme-change and
  internationalization-sensitive modifiers are explicit.
- SSR, hydration, and RSC: not applicable to the Node governance tooling; public-component and
  relevant operations route the Next.js/RSC skill, and all four Next.js builds passed.
- Responsive and adaptive behavior: no visual surface is introduced; composed-artifact and
  component routes retain the applicable review skills.
- Integration: applicable; the contract integrates repository governance, status lifecycle,
  prompts, workflows, skills, CODEOWNERS, scaffold verification, root tests, and contributor
  guidance.
- Documentation: applicable and complete through the operating model, execution protocol, catalog
  indexes, README, handbook, contribution guide, and pull request template.
