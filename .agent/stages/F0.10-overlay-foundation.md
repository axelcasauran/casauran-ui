## Outcome

Outcome: COMPLETE

F0.10 establishes the internal framework-neutral overlay lifecycle foundation for governed portal
hosts, token-safe top-layer ordering, non-cascading dismissal, nested focus scopes, and native-
inert modal isolation. Ownership, security boundaries, strict typing, SSR/RSC import safety,
accessibility behavior, cleanup, documentation, mechanical validation, and three-browser
production evidence are complete without introducing a public component, positioning engine, or
F0.11 animation capability.

## Delivered scope

- Added a canonical versioned overlay registry and JSON Schema with five exact capabilities,
  evidence dimensions, owner package, and explicit owned/excluded boundaries.
- Implemented portal-host creation, same-document validation, idempotent cleanup, and explicit
  synchronization of only `data-theme`, `data-density`, and `dir` from the effective source scope.
- Implemented deterministic keyed overlay registration, replacement without reordering, top-layer
  lookup, explicit unregister/clear, and token-aware stale-cleanup protection.
- Implemented one centralized document listener pair for top-layer-only unmodified/non-repeating/
  non-composing Escape and primary pointer-down outside the layer and logical branches. Dismissal
  is a typed intent and cannot cascade to a newly exposed parent in the same event dispatch.
- Implemented per-document nested focus scopes with explicit/first-tabbable/fallback/root entry,
  current-DOM Tab/Shift+Tab containment, outside-focus recovery, parent suspension, and ordered
  restoration. Invalid outside entry targets and command-modified/composing Tab are ignored.
- Implemented reference-counted native-`inert` isolation along modal ancestor/sibling branches,
  preserving preexisting inertness and nested ownership through token-safe idempotent cleanup.
- Added five validator regression tests, four pure/server-import tests including a deterministic
  1,000-layer scenario, and five production browser scenarios per engine for SSR/hydration, portal
  scope/cleanup, nested dismissal, IME-safe Escape, focus containment/restoration, and inertness.
- Added only the existing internal accessibility package as the overlay runtime dependency and the
  overlay workspace link to the visual-test host; no external runtime dependency was introduced.
- Updated capability lifecycle, ownership/CODEOWNERS, architecture/accessibility/security/
  performance/Next.js/testing policies, engine/interaction/accessibility/rendering matrices,
  package/docs/test navigation, contributor guidance, root commands, mechanical governance, and
  the preceding F0.09 validator's legal overlay lifecycle handling.

## Enterprise applicability

- Functionality: applicable; future Popup/Tooltip/Popover/Dialog/Menu/dropdown/Window components
  receive one canonical portal, top-layer dismissal, focus, and isolation lifecycle rather than
  duplicating document-global mechanics.
- Typing/API: applicable; generic layer keys/records, readonly records, typed dismissal reasons,
  explicit handles, and optional target resolvers infer under strict TypeScript without third-
  party leakage. The package remains internal and creates no supported consumer API.
- Accessibility: applicable; nested scopes provide current-DOM focus entry/containment/
  restoration and native inert isolation, with real-browser keyboard evidence. The foundation
  renders no role/name/state, `aria-modal`, close control, announcement, or visible focus style and
  certifies no future APG pattern; component/manual review remains mandatory.
- Keyboard/pointer/touch/IME: applicable for top-layer unmodified Escape, primary pointer outside,
  Tab/Shift+Tab, branch-inside handling, and composition/command safeguards. Components own their
  complete pattern keyboard tables, close controls, touch target behavior, and open-state updates.
- Theming/density/RTL: applicable; portal hosts synchronize only governed theme, density, and
  direction scope values, including nested detached scopes. The nonvisual engine adds no CSS,
  component tokens, physical layout, or visual direction logic.
- i18n: not directly applicable; the engine emits typed machine reasons and no user-facing text or
  locale behavior. Components localize labels, descriptions, and announcements.
- Responsive/adaptive: not directly applicable because F0.10 owns no geometry/layout/viewport
  logic. Positioning and component stages define adaptive behavior.
- SSR/hydration/RSC: applicable and complete; package import has no module-evaluation DOM access,
  timer, random source, storage, network, React, or client directive. Browser mutations begin only
  after callers supply mounted nodes; production SSR and hydration are error-free in three engines.
- Security: fixed portal attributes are copied as plain text only; no arbitrary attributes, IDs,
  handlers, HTML, URLs, serialization, or dynamic execution exist. Event targets are constrained to
  the supplied document, and all listeners/owned mutations are disposable.
- Performance: top lookup is constant-time, stack order is deterministic, focus queries only the
  active scope, and isolation walks relevant ancestor/sibling branches. A 1,000-layer correctness
  case guards ordering/cleanup without making a universal timing, memory, or bundle claim.
- Integration/documentation: registry, schema, owner dependency, policies, package docs, production
  fixture, commands, tests, matrices, and contributor guidance are aligned and executable.

## Decisions, debt, and blockers

- No ADR was required because F0.10 implements accepted ADR-002 native/internal dependency first,
  ADR-004 browser API preference, ADR-007 package layering, ADR-008 minimal client boundaries,
  ADR-009 WCAG 2.2 AA, ADR-010 registry/spec before code, ADR-016 internal supported-package
  boundary, ADR-018 security gate, and ADR-999 architecture freeze without changing them.
- No external runtime dependency or public API was introduced. The existing internal accessibility
  focus owner plus native DOM `inert`, events, and element APIs satisfy the scoped capability.
- The local KendoReact corpus was not consulted because F0.10 is an independent platform
  foundation stage, not reference analysis. Platform accessibility/data-binding registries remain
  `unreviewed`.
- Focus restoration composed with modal isolation has an explicit sequencing contract: release
  inert isolation before deactivating the restoring focus scope. Cross-browser regression evidence
  covers this rule.
- Scroll locking/scrollbar compensation is explicitly excluded because modality and layout policy
  belong to future component requirements; this is a documented boundary, not hidden F0.10 debt.
- No F0.10 blocker or in-scope debt remains.
