# Workflow: parity-audit

## Purpose

Certify component feature/platform coverage.

## Entry conditions

- Active stage/phase known.
- Governing policies and relevant skills loaded.
- Acceptance criteria established.

## Procedure

1. load spec.
2. audit features.
3. audit cross-cutting dimensions.
4. verify tests/docs.
5. record gaps/improvements.
6. advance state with evidence.

## Records

- affected stage/phase
- decisions/evidence
- tests/validators
- debt/follow-up

## Hard gates

- visual match insufficient.

## Exit

Update authoritative registry/stage/status and stop at workflow boundary.
