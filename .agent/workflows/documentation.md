# Workflow: documentation

## Purpose

Create executable product docs.

## Entry conditions

- Active stage/phase known.
- Governing policies and relevant skills loaded.
- Acceptance criteria established.

## Procedure

1. purpose/basic use.
2. API/events.
3. a11y/keyboard.
4. theme/RTL.
5. SSR/i18n.
6. edge cases.
7. runnable examples.
8. verify build/links.

## Records

- affected stage/phase
- decisions/evidence
- tests/validators
- debt/follow-up

## Hard gates

- docs ship with behavior.

## Exit

Update authoritative registry/stage/status and stop at workflow boundary.
